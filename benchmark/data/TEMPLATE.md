# vX.Y.Z 性能记录

本模板用于当前版本的基准归档。默认原生协议为 `android-native-v2`，App 协议为 `android-app-v2`。每台设备分别记录；缺少证据的单元格填写“未测”“不支持”或“失败”，保留失败和未完成记录，不以估算或零值替代。

## 版本与测量条件

- 版本 / commit / native source SHA-256：未填
- 状态：未测 / 部分完成 / 完整通过 / 失败
- 测量日期、原始 JSON 路径、历史基线归档路径：未填
- 清单：`android-native-v2` / `android-app-v2`；清单摘要取自原始报告
- 设备型号 / SoC / 系统 / 设备指纹：未填
- NDK / CMake / 构建类型 / ABI / harness 或 APK SHA-256：未填
- 模型、词表、shortlist、前缀表、语料 SHA-256：见原始 JSON
- 固定输入：FLORES-200 前 200 条；每场景 3 个独立进程，每进程 3 遍
- 采集范围：当前版本；仅显式请求配对测量时使用 AB / BA / AB 顺序
- CPU 亲和性、前台状态、起止温度/频率、降频和异常：未填

## 同配置版本比较

- 速度 = `输入条数 × 1000 / 耗时 ms`；倍率 = `旧版耗时 / 新版耗时`，提升 = `(倍率 − 1) × 100%`。原始耗时与全部场景保留。
- 严格比较要求相同清单、设备、模型、输入和计时范围的完整报告；旧版直接引用已归档基线，不自动重测。
- 记录检查命令、阈值、退出码及各项差值。协议或条件不一致、轮次不完整时标注不可直接比较，不据此计算版本性能收益或给出验收通过结论。
- README、版本对比和发布说明从 `source-index.json` 指向的归档生成，展示更新不触发采集。

## 默认参数收益与新增维度

默认参数变化须单独列明配置、来源和适用范围，不能替代固定协议结果。新增维度采用新的清单版本并保留已有定义。补测只在明确请求后新增带日期的记录，不覆盖旧报告。
