# v0.5.0：与 v0.3.0 / v0.4.0 的差异

2026-09-15 测量，**0.5.0 为本地候选版本，尚未发布**。性能对照已归档的 0.3.0 基线；体积和补充质量回测对照已发布的 0.4.0。以各报告的 APK / AAR / 二进制及源码指纹确定被测对象，不能混用不同产物的结果。原始记录在 [`raw/`](raw/)，机器可读索引见 [`index.json`](index.json)。

| 对照 | 项目 | 结果 |
|---|---|---|
| vs **0.3.0** | 200 条标准原生基准 | 8 场景、48 进程完成；耗时/RSS 在回归阈值内，日→中输出变化保留为检查失败（退出码 `1`） |
| vs **0.3.0** | 200 条标准 App / ML Kit | 改用 v2 六场景；当前版 8/18 进程，六场景各完成 1–2 进程；已停止追加测量，仅作参考 |
| vs **0.3.0** | 标准译文质量 | 英→中两版 App 译文相同；日→中改变 21/200 条，COMET 86.7131 → 86.7640 |
| vs **0.4.0** | AAR 体积 | 3,784,263 → 2,809,980 字节，减少 974,283 字节（25.75%） |

同口径原生对照中，0.5.0 热态速度相对 0.3.0 变化为 −0.2%～+6.6%，多数场景接近，不能宣称整体推理大幅提速。发行体积变化包含自有分句器替换、Android SentencePiece 训练代码裁剪等本次变更，不能全部归因于单一优化；AAR 不含模型权重或训练语料，包体变小也不代表推理一定提速。

[展示结果](derived/summary.json)由[生成器](../../../tools/benchmark-report/README.md)从 `raw/` 加工。后续仅采集当前版本，修改 README 或发布说明不触发设备测量。

## 小米 14 标准基准：0.3.0 → 0.5.0

本次原生 `android-native-v1` 已完成 **48 个配对进程 / 144 遍**。App 在取消四线程复测后改为 `android-app-v2`，随后按要求停止追加测量：**0.5.0 已完成 8/18 个进程 / 24 遍**，六个场景各有 1–2 个独立进程；原定第二轮部分场景和第三轮未测。不得标为完整稳定基线通过。

### 测量口径与来源

- 两套协议均使用原始 FLORES-200 devtest 前 200 条英、日源文，每个已完成进程完整翻译三遍，结果缓存关闭。首遍包括引擎/模型创建与翻译；热态取后两遍耗时中位数，再取已完成进程的中位数。速度为 `200000 / 耗时 ms`，不是 token/s；未清空系统文件缓存。
- 手机为 Xiaomi 14 / Snapdragon 8 Gen 3 / Android 16，起跑要求 CPU 2/7 频率上限 ≥ 2630400 kHz，最多等待 180 秒。原生绑 CPU 2–6、间隔 8 秒；App 正常前台调度、不绑核、间隔 15 秒。频率上限不是实际锁频；前后温度、亮屏、锁屏及焦点均有记录。
- 原生两版使用同一 NDK 29、Release 构建、历史 harness、语料及模型；前缀开启场景给两版传入同一份历史英语表。App 使用各版 SDK 默认规则，采样器除包名外一致；API 适配仍把引擎创建和翻译包在相同计时范围内。
- App 是 debug 基准 APK，原生库使用 Release 优化；PSS 每 250 ms 采样，包含 JVM/UI，不能与原生 RSS 相减，也不能冒充发布 R8 AAR 的独立打包测量。
- 旧 App APK 与历史归档 SHA-256 完全相同，模型目录在开始时按哈希对齐；[14 字节 ML Kit 元数据对齐记录](raw/mi14/standard/mlkit-state-alignment.json)保留。停止时未采集完整场次结束模型指纹，检查器据实报告这一缺项。

### 标准译文质量与评分复用

每个已完成进程的 200 条译文与评分按 SHA-256 关联。英→中 App 两版译文相同，COMET × 100 为 87.2672；日→中改变 **21/200 条**，COMET **86.7131 → 86.7640（+0.0509）**。ML Kit 英→中 72.6934、日→中 68.9276。见[App 差值](raw/mi14/standard/quality/app-comparison.json)、[候选版逐条评分](raw/mi14/standard/quality/v0.5.0-comet.json)。相同输出/参考译文/checkpoint 的得分直接复用已有评分，本次只为未评分的候选日→中输出执行一次模型评分，不重新运行翻译。

原生 blocking 场景另有 12 次译文导出，均与对应计时输出 FNV1a64 一致。原生固定历史英语表的日→中结果改变 13/200 条，COMET 86.7131 → 86.6838（−0.0293），近似逐行 bootstrap 95% 区间 [−0.1096, +0.0486]。它与 App 默认自有规则的输出不同，分别评分；不能用原生分数替代 App 分数。见[原生评分](raw/mi14/standard/quality/native-comet.json)与[差值](raw/mi14/standard/quality/native-comparison.json)。
