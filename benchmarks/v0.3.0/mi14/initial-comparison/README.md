# 小米 14：v0.1.0 → v0.3.0 性能参考

本组测试在系统当前调频状态下运行，两版均不等待频率上限恢复，保留相同场景、交替顺序与进程间隔。属于描述性性能对照，不作为严格回归基线。

命名口径：项目 README 中的“未优化版本 v0.1.0”指后续专项性能优化之前的对照版本。它已包含 ruy SDOT 内核编译修复和 CPU 指令集检测适配，不代表完全没有优化，也不是未经修改的 Mozilla 上游。

**48/48 个进程、144 遍翻译完成，无进程崩溃。** 默认单线程首次翻译速度为初版的 **2.02×（英→中）/ 2.12×（日→中）**，峰值 RSS 减少 **40.6% / 41.8%**。初版两个非默认 Blocking 场景未通过稳定输出检查；新版一个双线程场景的两项耗时波动超过 10%，见下表。

## 测试条件

| 项目 | 配置 |
|---|---|
| 设备 | 小米 14，骁龙 8 Gen 3，Android 16 |
| 初版 | v0.1.0，`d447381b1259a8f101a91390dd8950ad7080c84e`，本项目初版 Android 移植 |
| 最新版 | 本地 v0.3.0 快照，HEAD `bfc6a08c0aeaa8a679170d517c5c041a83c01834` |
| 构建 | 共用测试入口，arm64-v8a / Release / Android API 28 / NDK 29.0.13113456 |
| 输入 | FLORES-200 前 200 条英文或日文源文；两版共用模型、词表、shortlist 和语料 |
| 场景与重复 | `android-native-v1` 固定八场景 × 两版本 × 三轮；AB / BA / AB；每进程三遍 |
| 调度 | CPU 亲和性 `7c`（CPU 2–6），进程间隔 8 秒，结果缓存关闭 |
| 频率条件 | 显式启用 `--skip-frequency-gate`，两版均跳过起跑频率门槛；不修改系统温控或功耗设置 |
| 前台 | 每进程前后核验亮屏、未锁定、基准 app 获得焦点 |

版本、构建、设备和输入摘要见 [native-results.json](native-results.json)。

## 统计方法

- 首次速度为 `200 × 1000 / 首次耗时中位数（ms）`；首次含服务及模型创建、加载和首遍翻译，不含模型下载、进程启动或 JNI。
- 热态先取每进程后两遍耗时中位数，再取三进程中位数，最后换算条源文/秒。
- 峰值内存取首遍后的 native VmHWM，三进程中位数，单位 MiB；不与 app PSS 混算。
- 速度提升为 `(新版速度 / 初版速度 − 1) × 100%`；内存减少为 `(1 − 新版 RSS / 初版 RSS) × 100%`，从未舍入数据计算。
- 单格三进程的极差 / 中位数超过 10% 时标注，速度波动按原始耗时计算。缺失或失败格不计算性能中位数。
- 固定场景表按相同参数比较；默认配置表另比较初版 Async 1 / batch 1024 与新版 Blocking / batch 512 + 英文前缀表，包含默认分句与组批参数的收益。

## 结果

### 各版本默认单线程路径

| 语向 | v0.1.0 首次速度 | v0.3.0 首次速度 | 倍率 / 提升 | 峰值 RSS（初版 → 新版） | RSS 减少 |
|---|---:|---:|---:|---:|---:|
| 英→中 | 27.97 条/秒 | 56.61 条/秒 | 2.02× / +102.4% | 348.49 → 207.07 MiB | 40.6% |
| 日→英→中 | 12.79 条/秒 | 27.11 条/秒 | 2.12× / +111.9% | 530.37 → 308.46 MiB | 41.8% |

来源分别为 `v0.1.0: enzh_w1 / pivot_w1` 与 `v0.3.0: enzh_b512p / pivot_b512p`，包含默认参数变化。热态速度分别为 30.72 → 60.67 条/秒（1.97×）和 14.04 → 29.18 条/秒（2.08×）。这四格的首次耗时、热态耗时和 RSS 波动均未超过 10%，最高为 7.75%。

| 英→中 | 2.003× | 2.024× | 2.029× |

`3/3` 表示三个进程均完成翻译，不等于严格回归验收通过。旧版两个 Blocking 场景各九遍输出出现九个不同哈希，未通过清单的 `stable_hash` 要求，因此保留行和原始样本，不计算性能中位数。新版两个 Blocking 场景各九遍输出均一致。Async 场景按原清单不要求哈希稳定，不能将其性能结果解释为逐字输出不变。

† `v0.3.0 / enzh_w2_512p`：首次耗时三轮为 1974.193 / 2132.256 / 2253.571 ms，波动 **13.10%**；每进程热态耗时中位数为 1688.2115 / 1880.687 / 1902.147 ms，波动 **11.38%**。其余可统计格的三项波动均未超过 10%；完整数值由复核脚本输出。

### 系统条件与验收边界

起跑电池温度范围为 **33.2–37.0°C**。CPU 2 的上限出现 2,323,200 / 2,188,800 kHz 两档，CPU 7 出现 1,939,200 / 1,824,000 kHz 两档。两版都经历这些调频状态，所有进程的前后前台核验均通过，但各轮起跑频率上限并不完全相同；默认对照的温度跨度也超过严格检查的 3°C 线。

采集完成不等于验收通过：本场显式跳过频率门槛，且存在上述输出、波动和环境条件限制，严格检查器退出码为 `2`。未降低 10% 波动线，没有删除较慢样本，不用于替换已通过的 v0.2.0 → v0.3.0 严格原生基线。

## 复核与复现

[verify.py](verify.py)核对采集器及测试入口摘要、八场景、三轮顺序、样本完整性与工作负载，并重新计算描述性中位数、波动、同配置及默认配置差值。严格检查器仍对 `exploratory` 报告返回 `2`，不会因完成 48 个进程就将它标为通过。

[合成数据测试](test_verify.py)覆盖缺失样本、前台证据和不稳定 Blocking 输出的拒绝逻辑，合成数值不作为性能证据。

```bash
python3 benchmarks/v0.3.0/mi14/initial-comparison/verify.py
```

重新构建及准备设备见[工具说明](../../../../tools/version-bench/README.md)。在包含 `smoke-v0.1.0`、`smoke-v0.3.0` 和各版 manifest 的构建目录上运行：

```bash
python3 tools/version-bench/run-pair.py mi14 "$BENCH_BUILD/results-mi14-ungated.json" "$BENCH_BUILD" \
  --adb "$ANDROID_HOME/platform-tools/adb" --serial YOUR_DEVICE \
  --baseline v0.1.0 --candidate v0.3.0 --skip-frequency-gate
```

必须选择新的输出文件。使用已存构建复现时须保持原二进制；重新构建则使用 `--refs v0.1.0 --working-tree-version v0.3.0` 并核对源码摘要。本地快照标签不代表已发布 tag。

## 适用范围

这些数据只描述本机、本语料、本模型和本场系统调频状态。CPU 2 / 7 的上限快照不证明实际运行频率全程一致，也未覆盖 CPU 5–6 所属频率策略；交替顺序不能完全排除温度与后台调度的影响。本场不进行 COMET 质量评测，不能仅凭模型相同或性能改善推断译文质量不变。
