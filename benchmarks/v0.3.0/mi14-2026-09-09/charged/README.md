# 小米 14 · 充电后与前台状态复测

2026-09-09，手机重新接入时电量 86%。本次仍使用本地 v0.3.0 快照、原 APK/模型和固定测试协议，未修改引擎代码、系统性能模式或频率门槛。数据不与[上一场次](../reconnected/README.md)拼接，也不覆盖旧结果。

## 新增的运行条件检查

初次接入时发现：`am start` 返回成功，但设备仍处于 Dozing；唤醒屏幕后仍显示锁屏和 NotificationShade，不能据此认定基准 app 已在前台。随后确认屏幕 Awake、锁屏关闭且焦点属于基准 app。

[未完成前台核验的尝试](native-before-foreground-check.json)在屏幕唤醒带来的短暂频率恢复期间产生了一个原生进程、三遍输出。测试端在下一个进程等待频率时主动中止，退出码 130；该原始 JSON 没有全场完成标记，不是仍有后台作业。此场次不作为性能基线，也不用于填补后来正式场次。

采集器新增共享的 [bench_device.py 快照](collector/bench_device.py)：每进程前后记录屏幕唤醒、锁屏和焦点所属包，并在频率等待期间确认前台条件。缺少字段、Dozing、锁屏或焦点离开基准 app 时停止，保留已采集样本。原生采集器快照见 [run-pair.py](collector/run-pair.py)。

报告用 `foreground_checks: awake-unlocked-focused-before-after-v1` 标明新证据；检查器对带标记的报告强制核验前后快照。它没有改变八场景、三轮/三遍、语料、速度/RSS/PSS 定义或 10% 波动门槛。前后快照不等于连续证明全程前台。旧场次没有相同字段，不补写，也不能由本次锁屏观察倒推此前场次全程锁屏。

## 复现

先解锁手机，打开基准 app 的空闲页面，保持前台，不启动手动翻译、不与其他基准并行。按[原生工具](../../../../tools/version-bench/README.md)与[app 工具](../../../../tools/app-bench/README.md)分别使用新的输出文件/目录。电量高不保证频率门槛满足，仍须核对实际记录。

离线复核无需手机：在仓库根目录运行 `python3 benchmarks/v0.3.0/mi14-2026-09-09/charged/verify.py`。脚本重算原生/app 验收、全部固定行、超限原始值及质量映射。对应的 [verify.ipynb](verify.ipynb) 保存已执行输出；原生通过与 app 未通过分别呈现，不修改任何旧场次。
